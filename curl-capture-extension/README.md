# InventoryHub Order Capture (Chrome extension)

Captures the Taobao / Pinduoduo **order-list API request** straight from the
network layer and hands it to the InventoryHub import page — so you stop hunting
for the right request in DevTools and copy-pasting cURL.

## What it captures, and why the whole request

It serializes the real request (full URL incl. `sign`, all headers incl.
`Cookie` and Pinduoduo's `anti-content`, and the POST body) into a
`fetch(...)` string identical to Chrome's **Copy as fetch (Node.js)**. That
string drops into the existing import textarea and works with the existing
`/api/fetch` proxy and pagination helpers with no other changes.

It captures the **whole request**, not just cookies, on purpose: PDD's
`anti-content` and Taobao's mtop `sign` are per-session signatures generated by
the page's own JS. You cannot regenerate them from cookies, so a cookie alone is
not enough to rebuild a valid request.

## Install (unpacked)

1. Go to `chrome://extensions`, enable **Developer mode**.
2. **Load unpacked** → select this `curl-capture-extension/` folder.
3. Copy the extension's **ID** shown on the card.
4. In `inventory-hub-frontend/.env.local`, add:
   ```
   NEXT_PUBLIC_CAPTURE_EXTENSION_ID=<the id you copied>
   ```
   Restart `next dev`.

For production, add your app's origin to `externally_connectable.matches` in
`manifest.json` (e.g. `"https://your-domain/*"`).

## Use

1. Open your Taobao / Pinduoduo order list and **refresh once** (this fires the
   real request, which the extension captures). The popup shows ✓ + how long ago.
2. On the import page, pick the supplier and click **一键获取订单**. The page loads
   the orders from the latest capture.
3. If the import fails, refresh the order page and click again. To paste a command
   by hand, open **手动粘贴 fetch 命令（备用）**.

## Debug

1. Go to `chrome://extensions`. Click the reload icon on this extension's card.
2. On the same card, click **service worker** next to **Inspect views**. DevTools
   opens.
3. In the **Console** tab, filter by `[capture]`.
4. Refresh the order list page.

| Log line                     | Meaning                                       |
| ---------------------------- | --------------------------------------------- |
| `service worker started`     | The extension loaded.                         |
| `saw ...`                    | The extension saw an order request.           |
| `skipped ...`                | The request is not a POST. It was not stored. |
| `stored ...`                 | The capture was saved.                        |
| `import page asked for ...`  | The import page requested the capture.        |

Logs contain the method, request type, host, path and initiator. They do not
contain query strings, headers or bodies.

## Notes / limits

- **Freshness:** cookies, `_m_h5_tk`, `sign`, and `anti-content` are
  time-limited. The capture is the latest one; if a request fails, refresh the
  order page to capture a fresh one. (The capture is not a long-lived store.)
- **Security:** the capture contains live account credentials. It lives in the
  extension's `chrome.storage.local` and is only readable by pages listed in
  `externally_connectable`. Don't widen that list beyond your app.
- Pagination still replays the captured `sign` / `anti-content` across pages,
  exactly as the cURL flow does today.
